Serving Sebagai API
By definition, API (Application Programming Interface) adalah sekumpulan definisi dan protokol yang digunakan untuk membangun dan mengintegrasikan perangkat lunak aplikasi. API memungkinkan produk atau layanan Anda untuk berkomunikasi dengan produk atau layanan lain tanpa harus mengetahui cara implementasinya.

Dalam konteks machine learning, API ini ibaratkan seorang pelayan yang menghubungkan pelanggan dengan juru masak di sebuah restoran. Dengan kata lain, API bertindak sebagai jembatan antara model yang telah kita bangun dan aplikasi yang membutuhkan hasil prediksinya.

Memang benar, terdapat beberapa kasus ketika pelanggan dapat berkomunikasi langsung dengan juru masak, seperti yang sering kita lihat pada warung pecel lele, warteg, atau UMKM kuliner lainnya. Dalam analogi ini, komunikasi langsung dapat diartikan sebagai penggunaan model secara langsung di dalam kode aplikasi, tanpa melalui API.

Namun, pendekatan ini memiliki beberapa kelemahan dan kurang ideal dalam skenario deployment model machine learning yang sesungguhnya. Pertama, tidak semua "pelanggan" (aplikasi atau pengguna) memiliki keahlian atau akses untuk berinteraksi langsung dengan "juru masak" (model). Mereka mungkin tidak memahami bahasa pemrograman yang digunakan, cara memuat model, atau format data yang tepat. 

Kedua, "juru masak" (model) bisa kewalahan jika harus melayani banyak "pelanggan" (permintaan prediksi) secara langsung dan bersamaan. Hal ini dapat menyebabkan antrian panjang dan waktu tunggu yang lama. 

Ketiga, komunikasi langsung ini mempersulit pembaruan dan pemeliharaan model. Bayangkan jika kita harus mengubah "resep" (model) dan harus memberi tahu semua "pelanggan" (aplikasi) satu per satu tentang perubahan tersebut. Tentunya akan melelahkan terlebih jika terdapat pelanggan yang komplain.

Di sinilah peran API sebagai "pelayan" menjadi sangat penting. API menyediakan cara yang terstandarisasi dan efisien bagi "pelanggan" untuk memesan "hidangan" (prediksi) dari "juru masak" (model) dan meminimalisasi gangguan langsung terhadap model.

API bertugas untuk menangani semua detail teknis di balik layar, seperti format data, pemanggilan model, dan pengiriman hasil prediksi. "Pelanggan" hanya perlu tahu cara memesan melalui "pelayan" (API), tanpa perlu tahu detail rumit tentang cara "juru masak" (model) bekerja.

Dengan menggunakan API, kini siapa pun dapat memanfaatkan model machine learning tanpa perlu memahami proses kompleks yang terjadi di belakang layar. Pengguna cukup mengirimkan data ke API, dan model akan secara otomatis memprosesnya serta mengembalikan hasil prediksi dalam hitungan detik. 

Hal ini tidak hanya menyederhanakan proses inference, tetapi juga meningkatkan efisiensi dan pengalaman pengguna karena model dapat diakses kapan saja dan dari mana saja tanpa perlu menjalankan kode secara manual. Dengan demikian, integrasi model ke dalam aplikasi bisnis, layanan digital, atau sistem otomatisasi menjadi jauh lebih mudah dan praktis.

Menariknya, konsep API ini tidak terbatas pada satu "pelayan" atau satu instance saja. API memungkinkan kita untuk menyesuaikan jumlah layanan yang berjalan secara bersamaan sesuai dengan kebutuhan. 

Dengan kata lain, satu endpoint yang telah dibuat dapat digunakan oleh berbagai aplikasi atau sistem yang berbeda secara simultan. Bahkan, dalam skenario yang lebih kompleks, API dapat diperluas dengan konsep load balancing sehingga permintaan yang masuk akan didistribusikan ke beberapa server agar tetap responsif meskipun jumlah pengguna meningkat drastis.



Dockerize Machine Learning Model
Dengan Docker, kita bisa mengemas model machine learning beserta seluruh dependensinya ke dalam sebuah container yang membuatnya lebih portabel dan terisolasi dari sistem host. Pendekatan ini tidak hanya membantu dalam menjaga konsistensi lingkungan, tetapi juga mempermudah deployment, baik di server lokal, cloud, maupun infrastruktur berbasis container lainnya.

Secara definisi, Docker adalah sebuah perusahaan sekaligus platform yang menyajikan berbagai produk terkait container, mulai dari container engine (Docker Engine–produk inti Docker), container registry (Docker Hub), hingga aplikasi desktop (Docker Desktop) yang dapat membantu developer dalam mengembangkan, menyebarkan, dan menjalankan container. Meski Docker memiliki banyak produk, tetapi jargon Docker erat kaitannya dengan Docker Engine.

Sebagai container engine, Docker mampu mengemas dan menjalankan aplikasi di lingkungan yang terisolasi a.k.a container. Isolasi dan keamanan yang disajikan oleh Docker memungkinkan kita untuk menjalankan banyak Docker container (container yang dikelola oleh Docker) secara bersamaan pada host (mesin komputer/server) tertentu.

Pada dasarnya, Docker menggunakan arsitektur bertipe client-server. Dalam kasus ini, client-nya adalah Docker client, sementara yang menjadi server adalah Docker host (daemon). Docker client dan Docker host (daemon) dapat berjalan pada sistem yang sama (lokal) ataupun berbeda (remote). Keduanya saling berkomunikasi melalui REST API, UNIX socket, atau network interface.

Setelah mempelajari mengenal MLflow dan Docker, mari kita gabungkan kekuatan keduanya agar menjadi hard skill yang penting untuk seorang machine learning engineer. Dengan mempelajari cara mengintegrasikan Docker dan MLflow, nantinya Anda bisa membangun pipeline machine learning yang lebih robust, scalable, portable, mudah direproduksi, dan terhindar dari permasalahan works on my local machine.

Tantangan Serving
Setelah model mulai digunakan secara luas, tantangan sebenarnya muncul. Bagaimana jika jumlah permintaan meningkat secara tiba-tiba? Bagaimana memastikan latensi tetap rendah saat model diakses oleh banyak pengguna secara bersamaan? Bagaimana cara mengelola sumber daya agar model dapat berjalan dengan efisien tanpa membebani sistem? Lebih jauh lagi, bagaimana jika karakteristik data yang masuk berubah seiring waktu sehingga model tidak lagi memberikan prediksi yang akurat?

Tantangan-tantangan ini sering kali dihadapi dalam tahap serving yang modelnya harus tetap optimal dan dapat diandalkan dalam jangka panjang. Oleh karena itu, pemahaman mendalam tentang tantangan dalam model serving menjadi sangat penting sebelum masuk ke tahap implementasi lebih lanjut. Dengan memahami masalah yang mungkin terjadi, kita dapat merancang solusi yang lebih efektif untuk memastikan bahwa model tidak hanya berjalan, tetapi juga memberikan performa terbaik secara konsisten.

Nah, untuk memastikan model serving berjalan dengan optimal, kita akan mempelajari beberapa tantangan utama dalam model serving yang mencakup beberapa poin berikut.

Latency: Seberapa Cepat Model Merespons Permintaan
Salah satu aspek terpenting dalam model serving adalah seberapa cepat model dapat memberikan hasil setelah menerima input. Dalam dunia nyata, model yang terlalu lama memberikan respons bisa menyebabkan pengalaman pengguna yang buruk, atau bahkan membuat sistem tidak dapat digunakan sama sekali.
Scalability: Mampu Menangani Lonjakan Permintaan
Tantangan utama dalam scalability adalah memastikan bahwa sistem (restoran) tetap dapat memberikan respons yang cepat (makanan cepat disajikan) meskipun jumlah permintaan (pelanggan) meningkat secara tiba-tiba dan signifikan.
Resource Management: Mengoptimalkan CPU, GPU, dan Memori
Tantangan utama dalam resource management adalah bagaimana developer dapat mengalokasikan sumber daya komputasi (CPU, GPU, TPU, dan memori) secara optimal. Tujuannya agar model dapat berjalan dengan efisien (cepat dan memiliki throughput tinggi) tanpa menghabiskan terlalu banyak sumber daya (yang berarti biaya lebih rendah) dan tanpa menyebabkan sistem menjadi tidak stabil. Ini seperti menyeimbangkan antara kecepatan produksi pabrik, biaya operasional, dan keandalan mesin.
Untuk mengatasi permasalahan tersebut, terdapat beberapa pendekatan yang dapat Anda terapkan dalam proyek sistem machine learning yang andal. Beberapa pendekatan yang dapat dilakukan untuk mencapai resource management yang baik antara lain sebagai berikut.

Menggunakan Hardware yang Sesuai
Mengatur Batch Processing
Dynamic Resource Allocation (Alokasi Sumber Daya Dinamis)
Kesimpulannya, tanpa pengelolaan sumber daya yang baik, model serving bisa menjadi sangat mahal (karena pemborosan sumber daya) atau tidak dapat diandalkan (karena latency tinggi atau kegagalan sistem). Oleh karena itu, resource management adalah aspek yang sangat penting dalam membangun sistem model serving yang scalable, efisien, dan hemat biaya.

Kita telah mengidentifikasi empat tantangan utama dalam model serving yaitu Latency, Scalability, Resource Management, dan Data Drift. Keempat tantangan ini jika tidak ditangani dengan baik dapat menghambat keberhasilan implementasi model machine learning di dunia nyata, bahkan jika model tersebut memiliki akurasi yang tinggi di lingkungan pengembangan. Walaupun memiliki performa yang bagus, tetapi tetap saja model yang lambat, tidak scalable, boros sumber daya, atau tidak akurat karena data drift tidak akan memberikan nilai tambah yang diharapkan.

Pertanyaannya sekarang, bagaimana kita dapat mengatasi tantangan-tantangan ini dengan efektif? Nah, di sinilah peran tools yang kita pelajari dari awal yaitu MLflow kembali menjadi peran yang penting. Setelah berkelana kesana kemari, kita tahu bahwa MLflow bukan hanya sebuah alat untuk mengelola eksperimen selama tahap pengembangan model, tetapi juga menyediakan berbagai fitur yang dapat membantu dalam proses serving model. 

Salah satu keuntungan menggunakan MLflow kita dapat melakukan logging performa model secara real-time sehingga dapat memastikan bahwa model yang digunakan selalu dalam kondisi optimal. Selain itu, fitur Model Registry memungkinkan kita untuk mengelola versi model dengan lebih sistematis sehingga kita dapat dengan mudah melakukan rollback ke versi sebelumnya jika model yang baru tidak memberikan hasil yang diharapkan. Lebih jauh lagi, MLflow mendukung deployment model ke berbagai layanan cloud seperti AWS Sagemaker dan Azure ML yang dapat memberikan fleksibilitas dalam memilih lingkungan produksi yang sesuai dengan kebutuhan sistem.



Monitoring dan Logging
Monitoring
Monitoring adalah proses pemantauan model secara aktif untuk mendeteksi anomali atau perubahan performa dalam produksi. Tujuan utama dari monitoring adalah untuk memastikan bahwa model tetap berjalan sesuai harapan, memberikan prediksi yang akurat, serta menjaga efisiensi dalam penggunaan sumber daya komputasi.

Logging

Logging adalah proses pencatatan aktivitas dalam sistem model serving untuk keperluan analisis, debugging, dan pemantauan performa jangka panjang. Setiap kali model menerima permintaan dan menghasilkan prediksi, logging memastikan bahwa semua peristiwa tersebut dicatat dengan baik.



Mengatasi Permasalahan Serving
Setelah kita membahas berbagai macam tantangan serving termasuk latensi, mungkin tebersit sebuah pertanyaan di benak Anda “bagaimana cara mengoptimalkan latensi?” Nah, pada materi ini, kita akan membahas dua teknik utama yang dapat mengatasi permasalahan yang acapkali dibahas sebelumnya. 

Dua teknik utama yang akan kita bahas untuk meningkatkan efisiensi inferensi yaitu batching dan asynchrony. Kedua teknik ini berfokus pada pengurangan latensi dan peningkatan throughput sehingga model dapat melayani lebih banyak permintaan dalam waktu yang lebih singkat. Sebenarnya, ada banyak sekali metode yang dapat melakukan optimasi latensi, tetapi kita tidak akan membahas seluk beluknya karena materi tersebut akan dibahas pada kelas berikutnya.
