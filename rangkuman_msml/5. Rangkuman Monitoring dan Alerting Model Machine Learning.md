Rangkuman Monitoring dan Alerting Model Machine Learning


Komponen Monitoring
Seperti yang kita tahu bahwa setelah model machine learning di-deploy ke lingkungan produksi, tugas kita belum selesai. Model tersebut bukanlah entitas statis yang akan terus berfungsi dengan sempurna tanpa pengawasan seumur hidupnya. 

Sebaliknya, model machine learning yang beroperasi pada tahap produksi ibarat sebuah mesin yang perlu dipantau secara berkala untuk memastikan kinerjanya tetap optimal. Tanpa sistem monitoring yang efektif, kita seperti menerbangkan pesawat tanpa arahan artinya kita tidak tahu apakah pesawat tersebut terbang dengan benar, apakah ada masalah, atau apakah pesawat tersebut akan mencapai tujuannya.

Dengan kata lain, sistem machine learning tanpa proses monitoring dapat menyebabkan berbagai macam permasalahan tanpa terdeteksi. Walhasil, model bisa saja mengalami degradasi performa tanpa kita sadari. 

Hal tersebut bisa terjadi karena data yang masuk dapat berubah seiring waktu (data drift), penggunaan sumber daya bisa melonjak tanpa kendali, atau latensi API bisa meningkat hingga menyebabkan pengalaman pengguna yang buruk. Oleh karena itu, monitoring berperan sebagai mata dan telinga yang terus mengawasi sistem dan memberikan informasi secara real-time mengenai kesehatan model machine learning di lingkungan produksi. 

Untuk menjaga hal tersebut, monitoring dalam machine learning memiliki tiga komponen utama yang harus diperhatikan.

Monitoring Model: memantau performa model, akurasi prediksi, serta distribusi data input dan output seperti yang sudah kita pelajari pada modul-modul sebelumnya.
Monitoring Infrastruktur: memeriksa penggunaan sumber daya (CPU, RAM), latensi API, dan throughput sistem.
Alerting: menetapkan ambang batas performa atau sumber daya, serta memberikan peringatan otomatis jika batas tersebut terlampaui.
Setiap komponen di atas memiliki peran penting dalam menjaga keandalan model dan mencegah masalah besar sebelum berdampak luas.



Pengenalan Alerting
Setelah memahami pentingnya monitoring dalam sistem machine learning, kini saatnya Anda melengkapi kepingan puzzle yang hilang dengan mempelajari alerting. Jika monitoring berfungsi untuk mengumpulkan metrik dan memberikan wawasan mengenai kondisi sistem, alerting bertugas untuk memberi tahu kita secara real-time ketika ada sesuatu yang tidak beres.

Terdapat beberapa pendekatan untuk menentukan nilai threshold yang dapat Anda gunakan dalam alerting yang ada pada sistem machine learning (tergantung pada metriks yang akan dipantau). 

Threshold Statis
Ambang batas tetap yang telah ditentukan sebelumnya. Misalnya, penggunaan CPU melebihi 80% selama 5 menit, kirimkan alert atau jika latensi API lebih dari 500 ms dalam 10% request terakhir.
Threshold Dinamis (Adaptive Thresholding)
Menggunakan pendekatan berbasis statistik atau machine learning untuk menyesuaikan threshold berdasarkan pola historis data. Misalnya, jika latensi API meningkat lebih dari 3 standar deviasi dibanding rata-rata dalam 1 jam terakhir, kirimkan alert; atau jika anomali terdeteksi dalam distribusi data input model (data drift), kirimkan alert.
Rate-Based Threshold
Membandingkan nilai metrik dalam kurun waktu tertentu. Misalnya, jika jumlah error pada API meningkat lebih dari 5% dalam 15 menit terakhir, kirimkan alert atau jika terdapat lebih dari 100 permintaan dari satu IP dalam 1 menit, kirimkan alert untuk kemungkinan serangan DDoS.
Multi-Condition Threshold
Menggabungkan beberapa kondisi sebelum memicu alert. Misalnya, jika penggunaan CPU > 90% dan latensi API > 700 ms selama 10 menit, kirimkan alert.
Sebagai catatan, di luar strategi yang Anda pelajari di atas, tentu masih banyak sekali informasi yang perlu kita pelajari lagi. Namun, bukan berarti materi ini tidak lengkap karena saat ini seluruh hal yang berkaitan dengan AI sedang mengalami perkembangan sehingga Anda juga harus tetap berkembang agar dapat selaras dengan dunia.



Tools Pendukung Monitoring dan Alerting
Untuk menunjang model machine learning yang sudah ada pada tahap produksi, ada beberapa tools utama yang sering digunakan untuk mendukung proses monitoring dan alerting, yaitu MLflow, Docker, Prometheus, dan Grafana.

Prometheus
Prometheus merupakan sebuah tools monitoring (pemantauan) dan alerting (peringatan) yang bersifat open source. Ia mampu mengumpulkan dan menyimpan metrik dalam bentuk data time series. Proses pengumpulan metrik ini dilakukan dengan mengambil data dari endpoint yang telah Anda tentukan melui HTTP request. Selain itu, tool ini juga mendukung penggunaan PromQL yang merupakan bahasa query yang fleksibel dalam mengolah data hasil proses monitoring.

Prometheus bukan sekadar tools pencatat metrik biasa—ia memiliki arsitektur yang dirancang khusus untuk menangani data time-series dalam skala besar. Kemampuannya untuk secara otomatis mengumpulkan, menyimpan, dan menganalisis metrik dari berbagai sumber menjadikannya pilihan utama dalam sistem monitoring modern.

Grafana
Seperti yang telah disebutkan sebelumnya, salah satu kekurangan utama Prometheus adalah tidak adanya interface bawaan yang mudah dipahami. Meskipun Prometheus mampu menyimpan dan menganalisis data time-series dengan sangat baik, membaca metrik dalam bentuk teks atau kueri PromQL saja tidak cukup untuk memahami pola dan tren sistem secara cepat.

Berangkat dari kekurangan di atas, kita bisa menambal hal tersebut dengan tools tambahan yang sudah di-mention sebelumnya. Mari kita mulai dari hal yang paling sederhana, apa itu Grafana?

Grafana adalah tools visualisasi open-source yang dirancang untuk menampilkan data metrik dari berbagai sumber dalam bentuk dashboard interaktif. Tools ini sering digunakan dalam DevOps, infrastruktur cloud, hingga sistem machine learning untuk memantau performa model, server, dan API.

Tools ini menyediakan berbagai dashboard, bagan, dan grafik untuk berbagai data source (sumber data). Grafana memungkinkan kita untuk melakukan query, memvisualisasikan, dan menjelajahi berbagai metrics untuk data source yang dimiliki. Kita dapat membuat dashboard yang dinamis sendiri atau menggunakan template untuk monitoring dan visualisasi sistem.

Lalu, mengapa kita membutuhkan Grafana sebagai tools tambahan?

Mari kita perjelas kembali kekurangan Prometheus yang sudah kita spill sebelumnya. Meskipun tools tersebut mampu menyimpan dan menganalisis metrik, tetapi tools ini tidak memiliki tampilan visual yang memudahkan pengguna dalam membaca data. 

Sehingga, tanpa visualisasi yang baik, analisis metrik bisa menjadi sulit dan memakan waktu. Nah, untuk mengatasi permasalahan tersebut, kita bisa menggunakan Grafana sebagai pihak ketiga untuk membantu Prometheus melakukan hal berikut.

Melihat tren performa sistem dalam bentuk grafik.
Memantau metrik secara real-time.
Membuat dashboard kustom sesuai kebutuhan.
Mengatur alerting berbasis grafik visual.
Menyatukan data dari berbagai sumber ke dalam satu tampilan.

Pertanyaannya, bagaimana Grafana bekerja sama dengan Prometheus? 

Tenang, mari kita bahas sekilas sebelum memasuki bagian praktikum. Seperti yang kita sudah pelajari, Grafana dan Prometheus bekerja saling melengkapi dalam sistem monitoring. 

Prometheus bertugas mengumpulkan metrik dan menyimpannya dalam time-series database, sementara Grafana digunakan untuk menampilkan metrik tersebut dalam bentuk visualisasi yang mudah dipahami.



Monitoring Performa Machine learning
Dalam konteks sistem machine learning, terdapat dua aspek utama yang dapat Anda tentukan, yaitu metrik model dan metrik sistem. Sebelumnya kita sudah mempelajari bahwa metrik model berfokus pada performa prediktif model, sedangkan metrik sistem mengukur efisiensi dan keandalan infrastruktur yang menjalankan model tersebut. 

Bagaimana Menentukan Metriks Model?
Metriks model adalah nilai yang digunakan untuk menilai kualitas hasil prediksi dari model machine learning. Pemilihan metrik yang tepat bergantung pada jenis permasalahan yang sedang dihadapi, apakah itu klasifikasi, regresi, atau jenis prediksi lainnya. 

Untuk me-recall materi dasar, biasanya metriks utama yang umum digunakan dalam monitoring model itu antara akurasi, precision, recall, F1-Score, MAE, MSE, dan lain sebagainya tergantung tipe model yang Anda buat.

Selain metrik dasar di atas, distribusi prediksi juga (bisa jadi) perlu dipantau untuk mengidentifikasi adanya bias dalam model. Distribusi prediksi adalah bagaimana model menyebarkan probabilitas terhadap setiap kelas. Jika distribusi ini berubah secara signifikan setelah deployment, ini bisa menjadi tanda bahwa model mulai menunjukkan bias yang tidak diharapkan.

Bagaimana Menentukan Metrik Sistem?
Selain mengawasi performa model, sistem yang menjalankan model juga harus kita pantau (monitoring). Model dengan akurasi tinggi tetap bisa menjadi tidak berguna jika infrastruktur yang mendukungnya tidak berjalan dengan baik. Oleh karena itu, Anda harus bisa menentukan metriks sistem yang akan digunakan, seperti latensi, throughput, error rate, dan lain sebagainya.

Serupa, tetapi tak sama dengan metrik model, menentukan metrik sistem yang tepat bergantung pada tujuan utama dari layanan machine learning yang dijalankan serta ekspektasi performa yang diinginkan. Namun, terdapat beberapa pertimbangan yang secara umum digunakan oleh khalayak ramai seperti berikut ini.

Jenis Aplikasi dan Respons Waktu yang Dibutuhkan
Jika sistem digunakan dalam aplikasi real-time seperti chatbot, fraud detection, atau rekomendasi cepat, maka latensi API harus seminimal mungkin.
Jika sistem bersifat batch processing, seperti model prediksi cuaca atau analisis data bulanan, latensi mungkin kurang penting dibandingkan throughput.
Jumlah Permintaan yang Dapat Ditangani
Jika model di-deploy dalam skala besar dengan banyak pengguna, request throughput harus tinggi agar sistem tetap responsif.
Jika throughput rendah dan terjadi antrean panjang dalam pemrosesan permintaan, ini bisa menjadi tanda bahwa server perlu dioptimalkan atau ditingkatkan kapasitasnya.
Keandalan Sistem
Jika sistem mengalami banyak kegagalan, error rate harus dimonitor secara detail.
Jika ada peningkatan jumlah error seiring waktu, ini bisa menandakan adanya bug, kesalahan konfigurasi, atau kebutuhan untuk melakukan re-training model.
Kapasitas Infrastruktur
Jika server mengalami beban tinggi, metrik seperti CPU usage dan memory consumption juga bisa menjadi pertimbangan dalam menentukan kapasitas yang diperlukan.
Jadi, untuk menentukan metrik sistem yang tepat, kita harus memahami karakteristik aplikasi, ekspektasi respons waktu, volume pengguna, serta toleransi terhadap kesalahan dan kegagalan sistem. Dengan memantau metrik yang sesuai, kita dapat memastikan bahwa sistem tetap berjalan dengan optimal dan dapat menangani beban kerja secara efisien.

Deployment Model dengan API Docker Hub
Setelah image tersedia di Docker Hub, Anda bisa menggunakan images yang tersimpan pada Docker Hub pribadi Anda dengan menggunakan kode berikut.

docker run -d -p 5005:8080 <username>/<model>:<versi>
Dengan menjalankan kode di atas melalui terminal, Docker akan mencari images berdasarkan username, model, dan versi yang Anda tentukan. 

Jika ditemukan pada penyimpanan lokal, Docker akan mengonversi images tersebut menjadi container, Anda juga bisa menambahkan flag --name untuk memberikan nama container. Sebaliknya, jika Docker tidak menemukannya secara lokal, ia akan mencari images tersebut melalui Docker Hub dan mengunduhnya.

Logging dan Collecting Manual
Sayangnya, kapabilitas monitoring bawaan tersebut memiliki banyak sekali batasan salah satunya hanya memberikan informasi hasil inferensi tanpa mencatat kemanapun. Artinya, ketika API berhasil ataupun gagal melakukan inference, terminal tersebut hanya akan memberikan kode request, seperti 200, 400, dan lain sebagainya.

Nah, untuk melakukan monitoring dengan lebih detail Anda diharuskan membuat kode tambahan baik itu untuk performa model maupun sistem.

Namun, cara itu masih memiliki kekurangan karena Anda harus membuat kode dan mengonversi logs secara manual. Di lain sisi, kita juga akan kesulitan dalam memvisualisasikannya karena pada dasarnya Anda harus membuat dari scratch sehingga ketika ingin berhubungan dengan pihak ketiga harus membuat koneksinya terlebih dahulu.

Berangkat dari permasalahan tersebut, langkah berikutnya setelah logging manual adalah mengotomatiskan monitoring menggunakan alat seperti Prometheus dan Grafana untuk melihat tren performa model secara real-time. Walaupun tidak sepenuhnya otomatis, setidaknya dengan menggunakan kedua tools tersebut, kita bisa menggunakan fungsi yang sudah disediakan sehingga mempermudah proses logging dan monitoring.

Analisis Data Monitoring
Di titik ini, kemampuan critical thinking Anda sangat diperlukan untuk mengidentifikasi permasalahan dan mencari solusinya. Misal, Anda harus mendapatkan notifikasi bottleneck yang menghambat performa sistem seperti beberapa contoh berikut ini.

Latensi Tinggi: jika latensi API model terlalu tinggi, kemungkinan penyebabnya adalah ukuran model yang terlalu besar, penggunaan sumber daya yang tidak optimal, atau beban server yang berlebihan.
Solusi: Anda bisa saja menggunakan teknik model pruning untuk mengurangi kompleksitas model, menerapkan quantization agar model lebih ringan, atau meningkatkan kapasitas infrastruktur dengan auto-scaling.
CPU/RAM Usage Berlebih: jika penggunaan CPU atau RAM terlalu tinggi, bisa jadi model terlalu besar atau batch processing tidak optimal.
Solusi: mengurangi ukuran model dengan compression, mengoptimalkan teknik batching agar pemrosesan lebih efisien, atau mempertimbangkan penggunaan GPU/TPU jika workload sangat tinggi.
Throughput Rendah: jika jumlah request yang dapat diproses dalam satuan waktu terlalu kecil, penyebabnya mungkin adalah inefisiensi dalam deployment atau load balancing yang tidak optimal.
Solusi: menggunakan request batching, menerapkan load balancing, atau meningkatkan jumlah instance model dengan horizontal scaling.
Kesimpulannya, ketika Anda menerima notifikasi, berarti sedang terjadi anomali sistem yang harus diselesaikan apa pun itu masalahnya. Sebagai informasi, permasalahan yang muncul bukanlah sebuah hal yang pasti dikarenakan bergantung terhadap berbagai macam parameter.



Optimasi Performa Model
Setelah mengidentifikasi masalah dari hasil analisis data monitoring, langkah berikutnya adalah melakukan optimasi pada performa model yang terindikasi buruk agar proses inference lebih baik dan efisien.

Sebenarnya, langkah paling mudah untuk memperbaiki performa model adalah melakukan ret-training baik itu menggunakan data baru, gabungan dengan data lama atau bahkan melakukan online learning seperti yang sudah Anda pelajari sebelumnya.

Retraining Model
Seperti yang sudah Anda ketahui machine learning model pada dasarnya dibangun berdasarkan pola yang ditemukan dalam dataset pelatihan. Namun, dalam banyak kasus, pola dalam data dapat berubah seiring waktu, terutama jika model diterapkan dalam dunia nyata dengan data yang terus berkembang. Oleh karena itu, selain memerlukan monitoring, sistem machine learning juga perlu dilakukan retraining model menggunakan data terbaru agar model tetap relevan dan mempertahankan akurasinya.

Nah, pada materi sebelumnya, Anda sudah mempelajari berbagai macam pendekatan untuk melakukan re-training tersebut. Anda bahkan sudah melakukan praktikum menggunakan incremental learning, transfer learning, atau fully re-training.

Apa pun pendekatan re-training Anda akan menghadapi beberapa tantangan yang perlu dipertimbangkan seperti berikut ini.

Waktu dan Sumber Daya: pelatihan ulang model sering kali memerlukan sumber daya komputasi yang besar.
Overfitting pada Data Baru: jika tidak dilakukan dengan benar, model bisa terlalu menyesuaikan diri dengan data terbaru dan kehilangan generalisasi terhadap data lama.
Memilih Kapan Melakukan Retraining: menentukan frekuensi retraining yang optimal sangat penting agar tidak membuang sumber daya secara tidak perlu.

Fine-Tuning Hyperparameter untuk Meningkatkan Performa
Alih-alih menggunakan data baru untuk membangun model, Anda dapat memperbaiki performa model machine learning hanya dengan melakukan optimasi hyperparameter. Ini merupakan langkah yang lebih murah dan mudah dibandingkan melakukan pendekatan sebelumnya.

Model Pruning untuk Mengurangi Latensi
Model pruning adalah teknik untuk mengurangi kompleksitas model dengan menghilangkan bagian yang tidak terlalu penting sehingga mempercepat inferensi dan menghemat sumber daya komputasi.

Pruning memberikan beberapa keuntungan kepada sistem machine learning Anda kurang lebih seperti berikut.

Mengurangi Latensi Inferensi: model yang lebih kecil dapat dijalankan lebih cepat, terutama pada perangkat dengan keterbatasan sumber daya.
Menghemat Memori: pruning membantu menurunkan jumlah parameter yang harus disimpan dan diproses.
Meningkatkan Efisiensi pada Deployment: model yang lebih ringan dapat diimplementasikan pada edge devices seperti smartphone dan IoT.

Quantization & Compression
Quantization dan compression adalah teknik yang bertujuan untuk mengurangi ukuran model agar dapat digunakan dengan lebih efisien, terutama dalam lingkungan dengan keterbatasan komputasi.

Dengan mengurangi ukuran model, tentunya Anda akan mendapatkan beberapa trade-off, baik itu berupa keuntungan ataupun kekurangan. Pada dasarnya, quantization ini akan memperkecil ukuran bit yang model Anda simpan sehingga dapat mengurangi presisi atau performa model.



Optimasi Infrastruktur Model Machine Learning
Setelah Anda berhasil mengoptimalkan model machine learning dari segi akurasi dan efisiensi, langkah selanjutnya adalah memastikan bahwa model dapat berjalan dengan baik dalam lingkungan produksi. Optimasi infrastruktur menjadi pilihan yang penting untuk menangani lonjakan permintaan inferensi, memastikan latensi rendah, serta mengoptimalkan penggunaan sumber daya komputasi.

Scaling Model Deployment
Pada dasarnya scaling ini memiliki dua pendekatan yang sering digunakan yaitu vertical dan horizontal scaling.

Bagi beberapa orang mungkin sudah dapat menyimpulkan perbedaan dari gambar di atas, tetapi mari kita jelaskan perbedaan kedua pendekatan tersebut agar ramah bagi pemula.

Vertical Scaling (Scaling Up)
Meningkatkan kapasitas server dengan menambah CPU, RAM, atau GPU.
Tidak membutuhkan perubahan dalam arsitektur sistem.
Cocok untuk aplikasi dengan workload yang tidak terlalu fluktuatif.
Kekurangan: biaya tinggi dan ada batas fisik dalam peningkatan hardware.
Horizontal Scaling (Scaling Out)
Menambah jumlah instance model untuk menangani lebih banyak permintaan inferensi.
Memungkinkan sistem untuk menyesuaikan kapasitas secara dinamis berdasarkan beban kerja.
Keuntungan utama: lebih fleksibel dan lebih reliabel dibandingkan vertical scaling.
Tantangan
Memerlukan load balancing untuk mendistribusikan request dengan efisien.
Pengaturan yang cukup sulit untuk melakukan inference dengan model besar yang membutuhkan spesifikasi besar.



Auto-Scaling Model Inference Menggunakan Kubernetes
Kubernetes (sering disingkat K8s) adalah sistem orkestrasi container open-source yang digunakan untuk mengelola deployment, scaling, dan operasi aplikasi berbasis container secara otomatis. Kubernetes dikembangkan oleh Google dan sekarang dikelola oleh Cloud Native Computing Foundation (CNCF).

Ada berbagai macam pilihan yang disediakan oleh Kubernetes untuk melakukan auto-scaling pada sistem machine learning yang kelak akan dibangun. Berikut adalah fitur auto-scaling dari Kubernetes yang perlu Anda ketahui.

Horizontal Pod Autoscaler (HPA)
Kubernetes dapat menyesuaikan jumlah pod (unit komputasi dalam cluster Kubernetes) berdasarkan metrik yang dikonfigurasi. Contoh metrik yang digunakan yaitu CPU utilization, memory usage, atau jumlah request. Misalnya, jika penggunaan CPU setiap pod mencapai lebih dari 70%, Kubernetes akan menambahkan pod baru untuk menangani beban kerja.
Vertical Pod Autoscaler (VPA)
Secara otomatis meningkatkan kapasitas CPU/RAM dari pod yang sudah ada. Berguna untuk model dengan workload yang lebih tetap, tetapi memerlukan restart pod untuk mengalokasikan sumber daya baru.
Cluster Autoscaler
Menyesuaikan jumlah node dalam cluster Kubernetes berdasarkan jumlah pod yang berjalan. Jika semua pod membutuhkan lebih banyak sumber daya daripada yang tersedia, Kubernetes akan menambah node baru.
Dengan menggunakan salah satu pendekatan di atas, Anda dapat meminimalisasi permasalahan infrastruktur karena sistem machine learning akan menyesuaikan kebutuhan computing berdasarkan jumlah requestnya.



Load Balancing
Anda dapat menerapkan konsep load balancer sehingga sistem machine learning yang dibuat bisa menangani setidaknya beberapa permasalahan seperti berikut ini.

Menghindari Overload pada Satu Instance Model
Tanpa load balancing, instance tertentu bisa mengalami beban berlebih yang menyebabkan peningkatan latensi inferensi atau bahkan kegagalan layanan.
Meningkatkan Throughput Inferensi
Load balancer dapat mengarahkan request ke instance yang lebih sedikit digunakan, meningkatkan efisiensi sistem.
Meningkatkan Ketersediaan dan Fault Tolerance
Jika satu instance mengalami kegagalan, request dapat dialihkan ke instance lain yang masih aktif.
Mungkin tebersit sebuah pertanyaan di benak Anda “Bagaimana cara kita menerapkan load balancing ini?” Tenang, mari kita bahas tiga metode yang biasanya digunakan untuk mengatur jumlah request yang masuk seperti berikut ini.

Round Robin: setiap request dialokasikan secara bergiliran ke setiap instance yang tersedia.
Least Connections: request dikirim ke instance yang memiliki jumlah koneksi paling sedikit.
Weighted Load Balancing: setiap instance diberikan bobot berdasarkan kapasitasnya sehingga instance yang lebih kuat menangani lebih banyak request.
Di luar tiga metode di atas, apakah tidak ada lagi yang lain? Tentu saja tidak, sebenarnya terdapat banyak sekali metode load balancing yang dapat Anda terapkan.



Optimasi Penggunaan Sumber Daya
Anda harus pandai mengatur strategi optimasi sumber daya agar dapat memaksimalkan potensi dari laptop jaman pra-sejarah. Berikut beberapa pertimbangan yang dapat Anda lakukan untuk memaksimalkan sumber daya yang dimiliki.

Memanfaatkan Mixed Precision Computation
Anda dapat menggunakan kombinasi floating-point 16-bit dan 32-bit untuk mempercepat inferensi tanpa kehilangan akurasi yang signifikan. Memang hal ini cukup rumit untuk diimplementasikan. Namun, pilihan selalu ada, baik itu menggunakan hal yang rumit, tetapi murah atau mudah, tetapi mahal.
Menjalankan Model dalam Mode Asynchronous
Daripada menunggu satu request selesai sebelum menangani yang lain, model bisa diproses secara paralel menggunakan teknik asynchronous inference.
Optimasi Model dengan Quantization & Pruning
Mengurangi ukuran model dengan quantization (menggunakan bilangan bulat daripada floating-point) atau pruning (menghapus parameter yang tidak terlalu penting) seperti yang sudah kita pelajari sebelumnya.



Menyesuaikan Request Batching untuk Inference
Request batching adalah teknik yang menggabungkan beberapa permintaan inferensi sekaligus agar dapat diproses dalam satu eksekusi model sehingga dapat meningkatkan throughput inferensi. 

Sebagai catatan, metode ini sangat tidak direkomendasikan ketika Anda membangun sistem machine learning yang bekerja secara real-time. Namun, jika Anda tidak membutuhkan response secara langsung, metode ini sangat bagus karena dapat meningkatkan beberapa aspek seperti berikut ini.

Mengurangi Latensi per Request: alih-alih menangani satu request dalam satu waktu, batching memungkinkan model memproses banyak request sekaligus.
Efisiensi Komputasi: GPU dan TPU bekerja lebih baik ketika menangani batch besar dibandingkan satu per satu request.
Mengurangi Overhead: mengurangi jumlah panggilan ke model sehingga mengoptimalkan penggunaan sumber daya.
